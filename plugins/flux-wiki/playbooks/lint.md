# 手册:知识库体检(lint)

个人库 = `{{WIKI_ROOT}}`;`wiki-cli` = `{{WIKI_CLI}}`。
检查是确定性的(同一库任何机器同结果);AI 负责判读 + 给修复建议;**动手修复前需用户确认**。

## 流程

1. **环境层**先跑 `wiki-cli doctor`:配置路径活性 / 团队仓分支与水位 / 部署物在场性,
   有 ❌ 按输出里的修复命令处理(通常是 config 改一行或重跑安装)。
2. **内容层**跑 `wiki-cli lint`。检查覆盖:
   - ❌ error:`_routes.md` 必加载列指向不存在的文件(会让 AI 加载失败,唯一的硬伤级)
   - ⚠️ warn:死链(`[]()` 与 `[[wikilink]]` 两种写法,URL 编码如 `%20` 会先解码)/ 路由可选加载列解析不到(基准:必加载页所在目录或库根)/ 跨主题同名重复页(modules/ 内的协议骨架同名页不算)/ 路由关键词歧义 / 学习页溯源残缺(有 learned_from 缺 learned_commit)/ 词表闭集(库根有 `_vocabulary.md` 时:必填字段缺失、枚举字段取值越界,按字段聚合报)/ v2 旧布局提示(用户拍板保留时建 `.wiki/ack-legacy-layout` 空文件可静默)
   - 用户自建目录、自由组织、无 frontmatter 的页 **不算问题**(这是设计,不要"修复"它们)
   - 团队仓也可体检:仅当其根目录有 AGENTS.md 等 wiki 标记时 `wiki-cli --root <团队仓> lint` 可用(对非配置个人库的目标,CLI 按只读对待、不落审计文件);**报"不是有效 wiki 根"就到此为止,绝不对团队仓跑 init**
3. 判读报告:逐条说明影响与建议(修 / 忽略)。
4. **用户确认后**再动手修;涉及删页一律 `mv` 到 `archive/<YYYY-MM-DD>/`,绝不 `rm`。
5. 收尾:`log.md` 追加一行 lint 记录。全库体检 CLI 已自动落 `revisions/` 审计文件(输出里有路径),告知用户即可。
